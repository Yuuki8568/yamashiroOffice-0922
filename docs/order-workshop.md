# 発注工房：初期デモの仕様と検証

2026-10-23 / ホームページ内 `/demos/order-workshop/` に配置。
業務ツールデモスイートの掲載・リンクを差し替える。旧外部サイトそのものは削除しない。

## 目的
販売実績から予測を更新し、発注担当者が根拠・不足・余剰を理解して承認できる体験。
「すべての事象を織り込む」「使うほど必ず精度向上」「実際のAI自動発注」は約束しない。
架空小売店・4商品・84日間の合成データ。入力はブラウザ内で処理。ネットワークAPIなし。

## 実装
- モデル：曜日別直近最大8件平均、曜日ダミー＋気温＋雨＋販促＋イベントのリッジ回帰（正則化2、切片0.001）。負の需要は0へ。
- 初期合成データを用いて数値的に係数を学習。固定の説明文だけでAIを装うものではない。
- 直近最大112件を学習候補にし、欠品・休業・未確認日を除外。欠品中の潜在需要の補完はしない。
- 直近最大14有効日の逐次検証：各予測日より前の実績28日以上で学習して比較。最低42有効日・7検証日未満では承認停止。
- 日別の実測共変量を使った条件付き検証であり、天気予報自体の誤差は含まない。モデル選択に使用するMAEは独立な最終評価ではない。
- 販売実績を確定する直前の予測を別途記録し、入力後の実績と比較。休業・欠品・未確認はこの評価からも除外。
- シナリオ条件は今後14日間共通。曜日は日別。気温・雨・販促・イベント・遅延0〜5日・補充間隔1〜5日・安全係数0/1/2・予算・休業を変更可能。
- 既知の温度範囲より3℃以上外れた場合、経験のない雨/販促/イベント条件では承認停止。未経験の条件の組合せ検知は未実装。
- ロット別の期限を早い順に消費。入荷は当日朝、期限切れは当日販売後。期限前在庫・承認済入荷・販売を日別シミュレーション。
- 発注量＝入荷後の補充対象期間の不足＋MAE×安全係数×√補充間隔−対象期間末の余剰。最低数・ケース単位で切上げ、容量・期限内需要の上限で減量。
- 最長14日のシミュレーション内で追加廃棄・保管超過があればケース単位で減らす。長期品でも需要上限は14日内の分のみという保守的制約。
- 最適化や確率的なサービス水準保証ではない。需要の数値は期待値なので在庫試算には小数が出る。実績・発注数は整数。
- 同一日同一商品の重複承認禁止。予算は当日承認額で減額。入荷は一度だけ反映。未入荷の承認を取消可能。
- 数量手修正は理由必須。理由文からの自動学習は行わない。
- 明示操作でローカル保存、JSON入出力、式注入対策済CSV出力。監査記録は改ざん防止を備えないデモ用。

## 未実装・本番化の要件
POS、在庫台帳、天気予報、仕入先APIとの自動連携。定期ジョブ。複数利用者と認証・権限。実発注送信と重複防止キー。仕入先の営業日と締切。輸送カレンダー。返品・破損・複数期限別の棚卸調整。時刻を考慮した冷蔵品管理。SKUマスタとの同期。新商品・価格弾力性・代替購買・季節・祝日・災害・長期トレンド。複数店舗移動。モデル監視・ドリフト検知とロールバック。

まず店舗のデータを同意のもとに接続し、実発注せず従来発注との並行評価を行う。欠品・廃棄・在庫原価・担当者の修正率を確認してから段階的に承認連携する。

## スマホ対応（2026-10-23）
- PWA（manifest、アイコン、アプリ内キャッシュ）。スマホとPCで同じURL。保存は端末のブラウザ内で、端末間共有はない。
- ZXingのEAN/JAN、UPC、ITF読取。カメラ・画像・手入力に対応。画像はアップロードせず端末内で処理。チェック数字を検証する。自社デモコードは実商品コードではない。
- 最大30商品。新商品は学習履歴ゼロで登録し、十分な実績がない発注案は承認停止。商品名等をバーコードから外部検索する機能はない。
- 棚卸は理由と期限を必須とし、確認後に全ロットを一つの期限へ置換する簡易方式。複数期限を管理する本番用途には追加設計が必要。
- 実績を記録すると予測を再計算し、翌日の確認待ちを準備。承認前に在庫・条件・予算の変更を検知し、再作成を要求する。理由付き保留は再作成しても維持。
- 未承認の案は送信しない。承認も架空デモ注文のみ。操作と理由は履歴に残す。
- 設定時刻のポップアップはアプリ表示中のみ。OS通知は明示操作で許可を求めるテスト通知のみ。閉じている間の定時実行、Web Pushサーバー、実発注は未接続。
- 読み取りライブラリ再生成: `cd tools/order-scanner && npm ci && npm run build`。配布物にライセンス同梱。

### 本番接続の順序
1. 対象POS・仕入先の仕様、店舗、商品マスタ、発注締切、担当者・代理担当者を決める。
2. 認証と店舗権限、共有DB、入出庫・売上の取込、監査履歴を接続する。
3. 定時ジョブで予測・発注案を作り、確認通知と未確認時の再通知を送る。期限切れは保留。
4. 承認したスナップショットだけを重複防止キー付きで送信し、仕入先の受付応答と照合する。送信失敗と未受付を区別する。
5. 従来発注と並行評価し、欠品・廃棄・修正率・予測誤差を監視して段階導入する。
