MIGRATION / FIELD GUIDE · 2026-10-23

既存の仕事を止めずに、照合しながら移す。

公開版は移行検証用です。POS製品・契約プラン・実ファイルの形式が未確認のため、各社CSVの完全互換や本番運用の完了は保証していません。実発注・共有保存・自動連携は未接続です。

公式資料で確認した出力経路

Airレジ

バックオフィスから売上集計・会計明細・商品別の売上CSVを出力できます。期間合計だけの表では日別の学習に不足します。営業日×商品×数量が得られるか確認してください。商品別表にJANがない場合は、商品マスタの対応表を使います。

公式：売上データCSVの設定とダウンロード · 公式：商品別CSVの項目

スマレジ

「在庫 ＞ 入出荷 ＞ 仕入一覧」からCSVを出力する手順が案内されています。発注ID・入荷ID・仕入先・店舗・数量などを照合に使います。仕入一覧は入荷した情報なので、それだけで未入荷の発注残を表すとは限りません。発注側の台帳も別に確認してください。

発注登録では仕入先、発注日、商品、店舗への配分、予定日を設定します。CSVの項目と順番はアップロード設定に依存します。本デモのCSVをそのまま実発注用にアップロードしないでください。

公式：仕入一覧とCSV出力 · 公式：発注登録 · 公式：CSVフォーマット

実際の移行手順

  1. 元データを保管：元システムから対象店舗・期間を指定し、見出し付きCSVを出力。元ファイルは編集せずコピーで作業します。
  2. 単位とコードを確認：JANの先頭0を残すため文字列として扱います。Excelの指数表記・丸めで失われた桁は復元せず再出力します。ケースは入数を確認して個数へ変換。売価と仕入原価、税込と税抜を分けます。
  3. 少量で試す：1店舗・数商品から、商品 → 販売実績 → 棚卸 → 発注台帳の順に取り込みます。システムごとの列を手動で対応させます。
  4. 取込前に照合：行数、商品数、販売個数、在庫合計、発注数、入荷済数、未入荷残、税抜金額を元ファイルと比べます。エラーは全件修正して再検証。空欄を0と決めつけません。
  5. 担当者が確認して反映：JSONバックアップを取り、照合済みにチェックして反映。画面の数値と履歴を確認し、JSONを保存します。元のPOSの運用は継続します。
  6. 並行評価：同じ期間で従来発注と予測案を比較。欠品、廃棄、修正率、未入荷の二重計上を確認してから本番接続を設計します。

データの例外を隠さない

  • 同じ発注の分納は、発注数と累計入荷済数を区別。openは未完了、receivedは全数入荷、cancelledは取消。CSVによる状態更新は自動上書きせず、差分エラーとして照合します。台帳の「入荷状況を照合」で根拠を付けて更新できます。在庫は別途棚卸で確認します。
  • 販売返品・取消、値引き、単位違い、同名商品の別JANを勝手に合算しません。今回の日別実績取込は非負の整数が対象です。
  • 天候・販促・欠品等が不明な行は保存できますが学習から除外します。通常の売上CSVだけでは学習条件が揃わないことがあります。移行結果の「学習対象外」を確認してください。
  • 在庫取込は当アプリの計画日と基準日を一致させます。期限不明の在庫は仮の日付で埋めず、棚卸で確認します。
  • 取込は端末内で最大30商品（初期4商品を含む）、ファイル2MB・5000行。複数店舗の本番共有台帳ではありません。

本番運用へ進むための接続条件

POS名・プラン、匿名化した実ファイルの見出しと数行、対象店舗、仕入先の受付方法、締切と営業日、部分入荷・返品の扱いを確定します。その後、認証と店舗権限、共有データベース、バックアップ、承認権限、送信の重複防止、受付結果の照合、復旧手順を実装・検証します。

現在の公開デモだけを唯一の業務台帳にする段階にはありません。実際の発注・在庫更新は、接続先仕様と実データによる受入試験の後に切り替えます。
